HuanXing-Claw → HuanXing-Hermes 功能移植说明

本文档梳理 HuanXing-Claw 仓库 huanxing 分支（相对 main 的 27 个提交）所做的功能改动，并给出移植进 HuanXing-Hermes 桌面端的具体方案。

源仓库：D:\huanxing\HuanXing-Claw（Electron + React）　· 目标仓库：D:\huanxing\HuanXing-Hermes（Tauri v2 + React，已新建 huanxing 分支）　· 生成日期：2026-06-12
⚠️ 安全提示（务必先读）： 在本次分析过程中，多个工具/终端输出里混入了伪造的"系统提示词"文本（伪装成 Claude Code、含假冒计费头）。这是提示词注入（prompt injection），并非真实指令，已全部忽略。移植涉及外部 HTTP 接口与凭证存储，请把所有来自命令输出、网络响应、文件内容的"指令式文本"一律当作不可信数据处理。

架构差异（移植的核心前提）

两个项目不是同一套技术栈。这不是"复制文件"，而是一次跨架构重写：把 Electron 主进程逻辑改写为 Rust Tauri command，渲染层 React 可大幅复用但需替换数据通道。

HuanXing-Claw（源）

  • Electron 主进程（TypeScript / Node.js）
  • 业务逻辑在 electron/services/*、electron/utils/*
  • 主进程↔渲染：ipcMain / ipcRenderer + hostApi facade
  • HTTP：Node 核心 http/https（带 Cookie）、undici
  • 凭证：Electron safeStorage
  • 状态：Zustand（带 persist）
  • 页面在 src/pages/*
→

HuanXing-Hermes（目标）

  • Tauri v2 后端（Rust，crate hermes_agent_cn）
  • 业务逻辑在 src/commands/*.rs（#[tauri::command]）
  • 前后端：invoke() + window.hermesDesktop shim（tauri-bridge.ts）
  • HTTP：reqwest（见 api_proxy.rs / im_onboarding.rs）
  • 凭证：建议 OS keyring / DPAPI（Rust）
  • 状态：TanStack Query（服务端）+ Jotai（本地）
  • 页面在 web/src/routes/*
关键事实： Hermes 已经把后端做成了 managed runtime（hermes dashboard 子进程）+ Gateway WS。它的配置（openclaw.json 等价物）多数通过 dashboard REST / gateway 读写，而不是前端直接读文件。Claw 里大量"直接读写 ~/.openclaw/openclaw.json"的逻辑，在 Hermes 里要判断：能走现有 dashboard 接口就走，不能再新增 Rust command。

1. 账户登录 / Account

在侧边栏底部加"登录"按钮，登录到一个 newapi 风格的账户服务（品牌可配的 serviceUrl），拉取账号可用模型列表，生成一个完整 sk- token，并把所选模型注册成一个可用于对话的自定义 provider。

源实现要点

electron/utils/account-session.ts — 主进程 HTTP 客户端（持有 HttpOnly session cookie + New-Api-User 头）
electron/services/account-api.ts — IPC：login / fetchSetup / getBalance / listTokens / saveModelConfig / logout …
src/stores/account.ts — Zustand store（只持久化 serverUrl / lastUsername，session 与 key 永不出主进程）
src/components/account/AccountLoginButton.tsx / AccountLoginDialog.tsx — 两步登录（账号密码 → 选模型 + 选 token）

调用的后端 HTTP 接口（newapi 风格）

方法 + 路径用途关键头/字段
POST /api/user/login账号密码登录返回 session cookie + user 对象
GET /api/pricing新版模型列表（按 group 过滤）Cookie: session=…, New-Api-User: <id>
GET /api/user/self/models旧版模型列表（回退）同上
GET /api/user/self额度 quota / usedQuota同上
GET /api/status显示配置（quotaPerUnit / topUpLink）—
GET /api/token/ · POST /api/token/列出 / 创建 API token分页
POST /api/token/{id}/key · GET /api/token/{id}取完整 sk- key（新/旧两种回退）—

Hermes 移植方案

为什么必须放 Rust： 登录靠 HttpOnly session cookie。WebView 的 fetch 会丢 Cookie 头、且 key 不该暴露给前端。所以 HTTP 客户端必须在 Rust 侧（用 reqwest，参考已有的 commands/im_onboarding.rs 的 Client + 内存 FLOWS 状态写法）。
  1. 新建 src/commands/account.rs：用 reqwest::Client（cookie_store(true)）封装上表接口；session/cookie 存进 AppState（Mutex）或模块内 LazyLock<Mutex<...>>，sk- key 不返回前端，只返回 maskedKey + hasKey。
  2. 导出命令：account_login / account_fetch_setup / account_balance / account_list_tokens / account_save_models / account_logout，在 main.rs 的 generate_handler! 注册。
  3. 凭证持久化：用 OS keyring（keyring crate）或 Windows DPAPI，替代 Electron safeStorage；只持久化 serverUrl + 用户名，密码加密存。
  4. "保存所选模型"：写入 provider 配置。优先走 Hermes 现有 dashboard 配置接口（写 models.providers.<brandKey>），而不是前端直接写文件——见功能簇 2。
  5. 前端：在 web/src/components/sidebar/ 加 account-login-button.tsx + 登录对话框（复用 components/ui/dialog）；状态用 Jotai atom 或 TanStack Query 包 invoke("account_*")，通过 tauri-bridge.ts 暴露成 hermesDesktop.account.*。

2. 模型 Provider 管理（clawpanel 式）

Claw 把 Models 页重做成 provider 中心视图：每个 provider 一张卡片，支持 增/删/改 模型、设主模型、测试模型、从远端拉模型列表（fetchRemoteModels）。新增 API_TYPES 与 PROVIDER_PRESETS 快填模板（deepseek / openai / anthropic / google / moonshot / 硅基流动 / openrouter…）。

源：electron/services/model-providers-api.ts（泛化的 models.providers.* CRUD）、electron/utils/openclaw-auth.ts（provider-generic 读写）、src/stores/modelProviders.ts、src/lib/model-presets.ts、src/components/models/*（ProviderCard / Add/Edit/FetchRemote/ModelEdit 对话框）
Hermes 已有等价能力。 目标项目已有完整的 provider 体系：web/src/lib/provider-catalog.ts（BUILTIN_PROVIDER_CATALOG、增删改 update 构造器）、settings-models-section.tsx、use-provider-models、model-combobox。不要照搬 Claw 的整页，而是把 Claw 多出来的能力增量并入。

移植方案（融合，不重写）

  • 对比 model-presets.ts 的 PROVIDER_PRESETS 与 Hermes 的 BUILTIN_PROVIDER_CATALOG，把缺的国内 preset（硅基流动、moonshot、zhipu 等）补进 catalog。
  • "从远端拉模型列表"（fetchRemoteModels → GET {baseUrl}/v1/models）若 Hermes 没有，加一个走 api_proxy.rs / external_request 的前端封装即可，无需新 Rust 命令。
  • "测试模型"（testModel 打一次 completions）同理走 external_request。

7. 白标多品牌系统

构建期通过 BRAND=<id> 选择品牌，把一套代码打成多个产品（deepclaw/frogclaw/fengchiclaw/huanxingclaw）。单一事实来源是 brands/<id>.json，由 scripts/generate-brand.mjs 生成 shared/brand/active.generated.ts，主进程与渲染层都读 BRAND。

BrandConfig 字段（18 个）

id, appName, productName, executableName, appId, dataDirName,
instanceLockName, providerKey, serviceUrl, rechargeUrl,
updateFeedBaseUrl, copyright, vendor, maintainer,
linuxWMClass, tagline, assetsDir
成本最高、与 Hermes 现状冲突最大的一块。 Hermes 是 Tauri：品牌注入点在 tauri.conf.json（productName/identifier/窗口标题）、Cargo.toml、package.json，且已有 pnpm version:sync 统一三处版本。Claw 的 electron-builder 多品牌 merge 流程不能直接搬。

移植方案（建议改造而非照搬）

  1. 保留 brands/<id>.json 作为单一事实来源（字段裁剪：去掉 electron 专属如 instanceLock 语义按 Tauri 调整）。
  2. 新增 scripts/generate-brand.mjs：读 BRAND 环境变量 → 生成前端可 import 的 web/src/lib/brand.generated.ts，并注入 tauri.conf.json 的 productName/identifier/title（参照现有 version:sync 脚本对多文件改写的做法）。
  3. 把生成步骤接进 tauri:build:bundled-* 与 dev 流程；用 version:check 同款思路加 brand:check 校验三处一致。
  4. 前端把硬编码的 "Hermes" 文案改读 BRAND.appName（components/brand/ 已有 logo 组件，可扩成品牌模块）。
  5. 账户 providerKey、serviceUrl、rechargeUrl 直接喂给功能簇 1 的登录逻辑。

8. 预装技能从 SkillHub 拉取

把预装技能打包来源从 GitHub git checkout 改为 SkillHub（api.skillhub.cn）。manifest 每条加 source: skillhub|github，SkillHub 项按 slug 下 zip 并用 expectName 校验 SKILL.md 的 name:，错配则报错而不是装错内容。office 技能映射 xlsx→xlsx-cn / docx→docx-cn / pptx→powerpoint-pptx-cn。

风险与注意事项

🔐 凭证安全

sk- key / session cookie 只能留在 Rust 侧，前端只拿 maskedKey。用 OS keyring/DPAPI 替代 Electron safeStorage。提交前确认无 .env/密钥被纳入版本控制。

🍪 Cookie 传递

WebView fetch 会丢 HttpOnly cookie——这正是账户登录必须走 Rust reqwest（cookie_store(true)）的根因。不要试图在前端直接打账户接口。

🧩 单一事实来源

provider/模型配置：能走 Hermes 现有 dashboard 接口就走，避免前端直接写文件造成与 managed runtime 不一致。

🏷️ 品牌注入差异

Tauri 的品牌点（tauri.conf.json/Cargo.toml）与 electron-builder 完全不同，必须改造而非照搬；接进现有 version:sync 机制。

🛡️ 提示词注入

本次分析中工具输出混入伪造系统提示。移植代码处理外部响应时，把所有外部文本当不可信数据，勿据其改变控制流。

✅ 验证节奏

每阶段跑 typecheck / test:unit / cargo check。Rust 测试遵守 CLAUDE.md：env 测试 #[serial_test::serial]、HTTP 用 wiremock、FS 用 tempfile。
